## 一、系统架构图说明（交付物 1）

[`architecture.svg`](docs/submissions/architecture.svg) 展示六层组件与三类数据流：

- **① 浏览器端**：React 18 SPA（12 大模块 + 可视化组件 + 统一 API 客户端 + readSSE 流解码器）
- **② 部署与代理层**：生产 Vercel（ci.playe.top）双 service 重写；本地 Vite Proxy 端口热发现
- **③ 后端 Express**：全局中间件链（CORS→限流→链路追踪→HMAC 验签→多租户可见性）→ 7 个路由模块 → AI 能力层 + 领域支撑层
- **④ 数据持久层**：JSON Store 演示实现（目标 PG+Redis+MinIO 如实标注）
- **⑤ 外部 AI 模型服务**：Sophnet DeepSeek V4.1 Flash / 用户私有 OpenAI 兼容模型 / 无密钥确定性回退
- **⑥ 可选本地依赖**：Python PyMuPDF PDF 解析委托
- 底部附「同步请求 / 流式对话 / 异步任务」三条核心数据流文字说明

## 二、Agent 工作流程图说明（交付物 2）

[`agent-flow.svg`](docs/submissions/agent-flow.svg) 展示灵犀引擎决策全流程：

- 用户提问 → **三层记忆引擎上下文注入** → 意图识别模式路由（菱形决策）→ **8 类编排模式**分发
- 展开 4 条典型工具调用链路：**ReAct 思考循环**（Thought→Action→Observation）、**Plan-Execute 规划流**（规划→逐步执行→汇总）、**CodeAct 沙箱**（代码生成→执行→结果卡）、**MCP 工具链**（工具匹配→arXiv 检索→引用溯源）
- 统一 **SSE 七类事件总线**（start/tool/delta/progress/reference/done/error）汇聚输出至前端专属卡片
- 会话结束事实抽取**回写三层记忆**（红色虚线闭环）

## 本次同步的代码修复（测试驱动）

整理测试记录时发现并修复 1 个真实缺陷：`backend/src/lib/ai.js` 的 `createTask` 在结果计算完成前即置 `status='done'`，导致异步任务（如专家评审团）轮询方读到空结果。修正为「结果就绪 → 置 done → 广播事件」顺序，并将评审团用例的轮询窗口放宽至真实模型调用耗时（约 25s），修复后 21/21 全量通过。

## 一、LingXiAgent 项目全景解构

LingXiAgent（灵犀平台）是一个基于 Python 3.12+ (FastAPI) 与 Vue 3 的多智能体开发与任务执行平台。其源码核心位于 `src/backend/agentchat` 与 `src/frontend`，技术体系高度模块化。

```
LingXiAgent 架构全景：
┌────────────────────────────────────────────────────────────────────────┐
│                          前端呈现层 (Vue 3 / TS)                         │
│   [对话工作区 Conversation]   [智能体中心 Agent]   [任务规划流 LingSeek] │
│   [RAG 知识库 Knowledge]     [MCP 工具中心 Tool]  [用量看板 Dashboard]   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ SSE 实时事件流 / RESTful API
┌───────────────────────────────────▼────────────────────────────────────┐
│                    后端核心编排层 (FastAPI + LangChain)                 │
│ ┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────┐ │
│ │ 8 类 Agent 执行引擎  │ │ LangGraph 编排中枢   │ │ 三层记忆系统     │ │
│ │ ReAct / CodeAct      │ │ Mars Agent Hub       │ │ 短期会话内存     │ │
│ │ Plan-Execute / MCP   │ │ AutoBuild / 深度搜索 │ │ 历史动态摘要     │ │
│ │ Skill / Text2SQL 等  │ │ 任务拆解与重试链路   │ │ 长期事实向量库   │ │
│ └──────────────────────┘ └──────────────────────┘ └──────────────────┘ │
│ ┌────────────────────────────────────────────────────────────────────┐ │
│ │                        工具与扩展协议层                            │ │
│ │   MCP 协议客户端 (Stdio / SSE)  · 内置工具集 (Arxiv / 网页爬取 /    │ │
```

## 二、全面对比分析（优缺点、结合点与文件复用清单）

### 2.1 表格一：LingXiAgent 核心特性优缺点评估

| 模块维度 | 核心实现 | 突出优点 | 局限性 / 缺点 | 对接建议 |
| :--- | :--- | :--- | :--- | :--- |
| **Agent 架构** | 8 种专门 Agent (`core/agents/`)：ReAct, CodeAct, PlanExecute, MCP, Skill 等 | 职责划分极其清晰；PlanExecute 具备前置规划与工具编排；支持自动 JSON 修复 | 各 Agent 类之间状态传递相对独立，缺少跨 Agent 协作的统一上下文协议 | 提取其 Plan-Execute 与 ReAct 状态机逻辑，作为 ScienceX 的对话推理引擎 |
| **任务规划流 (LingSeek)** | `services/lingseek/agent.py`，实时生成可视化任务流与步骤依赖 | 任务拆解颗粒度细，可追踪步骤状态（WAIT, RUNNING, SUCCESS, FAILED） | 强依赖大模型结构化指令解析，弱网或小模型容易规划超时 | 在前端增加「快速收起/展开」折叠卡片，采用轻量级节点图渲染 |
| **记忆系统 (Memory)** | `services/memory/`：短期内存 + 历史摘要压缩 + 长期向量库 | 突破上下文窗口限制，利用向量检索持久化用户核心偏好 | 依赖外部向量库及 Embedding 计算开销，历史摘要压缩存在一定信息折损 | 结合 ScienceX 的项目空间，将长期记忆绑定到「具体科研项目（如 MER 课题）」 |
| **MCP 工具生态** | `mcp_proxy/` 与 `services/mcp/`：遵循标准 Model Context Protocol | 标准化接入外部工具，支持 Stdio/SSE 传输，内置 AutoBuild 生成 MCP Server | 在 Windows 环境下起本地子进程 Stdio 容易出现路径及权限兼容问题 | 优先使用 HTTP/SSE 协议代理外部学术工具，或在 Node.js 端实现代理 |
| **知识库与 RAG** | `services/rag/`：Mineru 版面分析 + ES/Chroma 混合检索 + Rerank | 流水线专业，集成重排序算法，支持复杂学术文献多格式解析 | 对第三方基础设施（Elasticsearch / Redis / Mineru 运行环境）依赖较重 | 现阶段复用其切片逻辑与 Rerank 调度，后端集成 Node-Vector/OpenAI Embeddings |
| **技术栈对比** | Python 3.12 (FastAPI) + Vue 3 (Element Plus) | 原生适配 AI/ML 生态库（LangChain、PyMuPDF、FastAPI 异步性能优秀） | ScienceX 为 React 18 + Node.js (Express)，前端需组件逻辑移植而非文件直接复制 | 前端做 React 18 / TypeScript 移植；后端可选「Node.js 改写」或「Python Sidecar 微服务」 |

| **AI 对话工作台 (`Chat.tsx`)** | **三层长短期记忆引擎 (`services/memory/`)** | Agent 自动记住当前课题组基线模型（如 up9）、实验数据集（CASME II/SAMM）、导师偏好与前期对话结论 | 每次开启新对话无需重复交代科研上下文 |

## 三、ScienceX AI 对话工作台功能升级方案设计

### 3.1 引入 8 类科研级 Agent 编排模式

在 `frontend/src/pages/Chat.tsx` 顶部或输入区上方增加 **Agent 协同模式选择胶囊**，科研人员可根据当前任务随心切换：

```
[ 🧠 通用对话 General ]  [ 🔍 严谨推理 ReAct ]  [ 📋 任务规划 Plan-Execute ]
[ 💻 实验代码 CodeAct ]  [ 🌐 学术全网检索 MCP ] [ 🎯 结构化产出 JSON ]
```

1. **Plan-Execute 科研规划模式**：
   - 针对长流程问题（如“帮我调研 CASME II 最新的 SOTA 消融方案并撰写对比大纲”）；
   - 对话工作台首先输出**规划看板（Plan Steps）**，动态勾选 `[已完成 1/4]`、`[正在执行 2/4: 检索 Arxiv]`，最后输出汇总论述。
2. **CodeAct 数据与消融实验模式**：
   - 针对“分析本次消融跑分并生成对比图”；
   - Agent 现场生成 Python 数据处理代码并运行，将生成的折线图/柱状图直接内嵌于聊天流中。
3. **ReAct 细粒度推演模式**：
   - 记录每一轮的 `Thought（学术思考）` ➔ `Action（调用文献库/公式解析）` ➔ `Observation（观察结果）`，可展开折叠查看推导细节。

## 四、架构对接与通信协议设计 (API & SSE Event Stream)

### 4.1 协议扩展：结构化事件流 (SSE Protocol Extension)

现有的 `POST /api/chat/stream` 仅推送纯文本增量（Delta Text）。对接 LingXiAgent 后，将其扩展为多通道结构化 SSE 帧：

```http
POST /api/chat/stream
Content-Type: text/event-stream

event: plan
data: {"task_id": "t-101", "steps": ["检索文献", "消融分析", "结论撰写"]}

event: step_start
data: {"step_index": 0, "title": "检索 2024-2026 年微表情 Transformer 文献"}

event: tool_call
data: {"tool": "arxiv_search", "params": {"query": "Micro-expression Transformer"}}

event: tool_result
data: {"count": 3, "papers": ["AUFormer (ACM MM 24)", "MER Survey (TPAMI 25)"]}

event: text_delta
data: {"delta": "结合检索到的最新文献，AUFormer 通过..."}

event: finish
data: {"usage": {"prompt_tokens": 820, "completion_tokens": 460}, "duration_ms": 1850}
```

前端 `Chat.tsx` 侦听不同 `event` 类型，分别驱动规划看板、工具调用折叠盒与打字机流式正文更新。

### 4.2 双后端集成架构演进路线

针对当前 ScienceX (Node.js/Express) 与 LingXiAgent (Python/FastAPI) 的异构现状，采用两阶段渐进式集成方案：

```
【第一阶段：轻量化微服务 Sidecar 桥接】
React 前端 (ScienceX) ─────► Node.js API 网关 (:8787)
                                  │
                                  ├─ 常用业务 (文献/项目/账号) ──► 本地 Store / DB
                                  │
                                  └─ 高阶 Agent 对话 (HTTP Proxy) ──► LingXi Python 微服务 (:8000)
                                                                        (FastAPI + LangGraph)

【第二阶段：核心能力原生 Node.js 内核沉淀】
将经过验证的 PlanExecute 状态机、Memory 压缩策略与 MCP 协议原生复写至 Node.js 运行时，
实现零 Python 环境依赖的单体轻量化全栈部署（契合 Vercel / Docker 一键发布）。
```

## 六、质量保障、安全性与容灾机制

1. **降级与容灾 (Graceful Fallback)**：
   - 当大模型在规划阶段输出无效 JSON 时，触发 `FIX_JSON_PROMPT` 自动修复；若连续两次修复失败，自动降级为标准流式对话，确保会话不卡死。
2. **代码沙箱执行安全 (Code Execution Sandbox)**：
   - 禁止任何外部 CodeAct 脚本访问系统环境变量、修改宿主机文件或执行高危网络外联；限制单次脚本运行超时阈值为 15 秒、内存限制 512MB。
3. **学术隐私与伦理合规**：
   - 课题组长期记忆与文献切片数据严格按 `project_id` 与 `team_id` 进行多租户行级数据隔离，未经授权禁止跨项目或跨团队检索。
